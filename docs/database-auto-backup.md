# 数据库自动备份

失联记录恢复版本默认开启恢复保护。保护期间暂停前台自动备份和过期清理。下述周期策略描述解除保护后的行为。[恢复操作说明](media-recovery.md)

## 使用规则

应用首次打开、从后台返回时在后台线程检查。没有有效备份，或距离最近一次成功备份严格超过 5 天，会自动生成一份新副本并 Toast 提示保存位置。恰好 5 天不触发；成功的手动备份也会重置周期。页面切换、屏幕旋转和仅后台服务启动不新增检查会话。

固定保存位置为公共目录 `Download/bDouyin/backup/`。备份内容是完整数据库，包括下载记录、标签、AI 分析和本地偏好学习数据；不包含视频、封面、Cookie 或 API Key。没有上传服务器。

每次前台检查会删除严格超过 30 天的有效应用备份，**包括手动备份**，恰好 30 天保留。最近一份有效副本始终保留。到期时先备份再清理，新备份失败本轮不清理。未知文件、链接、时间不可信、无法验证及无访问权限的副本不自动删除。应用未打开期间不会定时唤醒备份或删除文件。

## 失败与恢复

- 自动备份成功显示 Toast；备份成功但清理不完整时单独提示，不把新副本认定为失败。
- 空间不足、权限不足或完整性校验失败会提示，失败不改变上次成功时间。同一进程自动失败后至少间隔 1 小时重试，手动备份不受限制；实际存储权限变化可解除冷却，重新检查。
- 任务由应用级协程持有，切换页面继续执行；系统杀进程后，下次打开重新判断。后台完成的结果等到前台显示一次。
- 设置页仍支持二次确认后手动备份和恢复。恢复完成重启进程。重装或换签名后，直接 File 无法访问的备份可通过“从文件选择”授予 SAF 读取权限，选择 `blitz_downloader.db`。
- 恢复前先在内部临时目录校验副本，校验通过后才替换数据库。自动备份、手动备份、恢复和清理使用同一互斥锁，恢复成功后禁止再执行本进程的自动检查，等待原有重启流程。

## 副本格式与诊断

新目录格式为 `backup_yyyyMMdd_HHmmss_SSS_<随机ID>/`，包含单文件数据库和 `manifest.json`。manifest 记录来源 AUTO/MANUAL、数据库版本、开始/完成时间、文件大小及 SHA-256。先写 `.pending_<ID>`，成功校验后原子重命名发布；半成品不会参与周期或进入普通恢复列表。旧版 `backup_yyyyMMdd_HHmmss` 的 DB/WAL/SHM 在隔离目录回放并校验后继续兼容。

实现使用一个源 Room 事务，逐行复制表数据及结构到内部临时 SQLite 数据库，随后恢复索引、视图、触发器、版本、Room identity 和自增序列；快照输出不依赖活动 WAL。校验结构、逐表行数、完整性及外键，并确认外部副本字节数和 SHA-256。源事务期间业务写入可能短暂等待，公共存储复制和哈希计算在事务外完成，不关闭共享 Room 连接。遇到虚拟表明确失败，避免静默漏数据。

`DatabaseBackup` 日志记录触发来源、最近成功时间、快照/总耗时、字节数和清理数量；不记录标签内容或密钥。时间回拨时停止清理并创建当前时间校准副本，使用已验证成功 ID 避免未来时间目录长期阻断周期。
