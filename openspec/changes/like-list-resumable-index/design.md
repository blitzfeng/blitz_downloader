## 背景与目标

点赞列表使用不透明的 `max_cursor` 正向分页。本功能的目标是退出后回到实际浏览位置，继续看尚未浏览的缓存，再向服务端续页；不是预先建立有限条数的索引。

## 三种位置必须分开

- **浏览锚点**：屏幕顶部首个可见作品的 `awemeId`、稳定 `sourcePosition` 和相对滚动视口顶部的像素偏移。三列网格保存首个可见行，因此恢复可能靠前一两条。
- **本地加载边界**：当前页面已经从数据库读到的条目偏移，仅用于本次分页，不代表用户看过。
- **远端分页检查点**：成功响应返回的 `nextCursor`、缓存唯一条目数与会话状态。完整分页入库后才在同一事务推进游标。

例如每页 30 条、已缓存 60 条、看到第 40 条退出：保留完整 60 条及第二页返回的 cursor，单独保存第 40 条所在行的锚点。恢复从锚点前一行开始读取本地窗口，布局完成后滚回该行；41—60 条不重新请求。接近缓存末尾时用保存的 cursor 拉下一页，不把 40 或 60 换算成 cursor。

## 采集与恢复

1. Fragment 从真正滚动的 `NestedScrollView` 视口计算首个可见网格项，扣除底部工具栏遮挡；不能直接使用内层 RecyclerView 的首项，因为它高度为 wrap_content。
2. 滚动停止 300ms 后保存，离开页面/切后台时补存；数据库写入串行化。浏览锚点不等同于逐条观看完成状态。
3. 保存按来源隔离，使用作品 ID 定位，来源序号作后备；恢复时只加载锚点附近及后面的缓存，避免重新装入全部历史条目。
4. 数据绑定、布局完成后恢复像素偏移。恢复期间禁止保存初始视口和滚动触发分页；确认恢复完成后解除。隐藏已下载导致锚点不可见时，使用其后的最近可见项，没有则取前方项。
5. 本地缓存读完后才使用远端游标；不足一屏时可自动补页，沿用有限自动补页保护，避免空页/全过滤情况下无限请求。不需要再点“解析”。
6. 分页检查点事务读取最新浏览锚点并保留，避免网络请求持有的旧会话覆盖滚动保存结果。

## 数据与迁移

Room v28 向 `liked_list_index_session` 增加可空的 `anchorAwemeId`、`anchorSourcePosition`、`anchorOffsetPx`；已有条目、游标和下载数据保持不变。旧 `lastViewedOffset` 实际保存的是加载边界，仅保留兼容，不再读写用于恢复。

旧版本没有真实浏览位置，不能凭空还原。升级后首次继续浏览从已有缓存起点显示，不重新下载历史分页；产生新锚点后按新机制恢复。

会话与条目以来源身份隔离，条目按 `(sourceKey, awemeId)` 去重。来源序号保持首次插入顺序，不因远端头部新增点赞而重新编号。条目缓存封面、视频地址及完整图集/实况配对，供展示；这些地址可过期，预览、选中及下载按既有流程重新解析媒体。

## 用户操作与边界

- 抽屉只保留“继续浏览”“重置”，使用时自动选中“点赞”；不提供 100/500 条上限或排序控件。
- 重置必须确认，仅清当前来源缓存、游标和浏览锚点，从 cursor=0 重建。
- 底部累计数是去重缓存总数，已经包含当前列表；不能把两者再次相加，也不能称为精确已看数量。
- 新增点赞不会改变本地锚点指向的作品；继续浏览不自动插入列表头部新点赞。需要看最新内容时显式重置。服务端不是冻结快照，删除、隐私变化、游标失效可能产生重叠或遗漏，不能承诺无遗漏；重复 ID 去重，异常保留缓存并提示恢复。
- 突然杀进程可能丢失最后 300ms 内尚未落盘的移动，正常退出/后台切换补存。旋转、过滤、尾部不足一屏可能使像素位置近似，但优先保持作品身份。
- 作品、收藏、收藏夹、合集沿用现有瞬态列表。本次仅实现点赞来源。

## 验证

纯 JVM 测试覆盖锚点窗口、缓存优先的分页边界、隐藏项回退及检查点与锚点交错写入；编译验证 Room DAO 和前向迁移注册。真机需验证 40/60 场景、横竖屏、退出重进、图集、隐藏已下载、缓存末尾续页与旧库升级，不能用 JVM 测试替代设备上的 Room schema 校验和视口效果验证。
