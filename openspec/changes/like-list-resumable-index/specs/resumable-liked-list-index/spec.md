## Purpose

为用户点赞作品列表提供按需加载、持久化并恢复位置的浏览会话。

## ADDED Requirements

### Requirement: 不受旧条数上限限制的按需浏览

系统 MUST（必须）仅使用前一成功响应提供的游标按需请求下一页。系统 MUST（必须）移除条数上限，旧会话不得因达到 100、500 或 1000 条而停止续页。

#### Scenario: 超过旧上限继续加载
- **WHEN** 已缓存 1,000 条且远端仍有更多数据
- **THEN** 向下浏览继续请求下一页并完整保存去重条目

#### Scenario: 索引到达列表末尾
- **WHEN** 点赞列表收到表示没有下一页的响应
- **THEN** 系统将任务标记为完成，并报告最终唯一条目数

### Requirement: 基于游标边界的可恢复索引

系统 MUST（必须）在每个点赞列表分页成功后持久化下一服务端游标和已索引作品标识。系统 MUST（必须）使用该保存的精确游标恢复中断任务，并必须以稳定的 aweme ID 去重。

#### Scenario: 中断后的恢复
- **WHEN** 索引任务在完成前已持久化续拉游标且随后中断
- **THEN** 恢复任务时系统使用保存的游标请求下一页，而不是重新从第一页开始

#### Scenario: 边界页与已索引作品重叠
- **WHEN** 恢复请求返回的 aweme ID 已存在于同一点赞列表索引中
- **THEN** 系统只保留该 aweme ID 的一个索引条目，并继续处理该分页

### Requirement: 显式游标恢复

系统 MUST（必须）将保存的游标视为不透明的服务端边界，而不是页码。当恢复请求不能产生有效的续拉分页时，系统 MUST（必须）保留现有索引、将任务标记为需要恢复，并提供用户主动从列表头部重新索引的入口。

#### Scenario: 保存的游标被拒绝或不可用
- **WHEN** 恢复未完成索引时发生认证、API 或无效续拉错误
- **THEN** 系统保留已有索引条目、记录恢复失败，并提供从游标零开始建立新索引的选项

### Requirement: 不累积 UI 的索引列表消费

系统 MUST（必须）让完成和部分完成的点赞列表条目可恢复浏览，保留来源顺序和作品创建时间；浏览界面使用来源顺序，不暴露排序控件。

#### Scenario: 使用部分索引
- **WHEN** 用户中断浏览后返回
- **THEN** 用户无需将此前页面加载进活动列表 UI，即可查看和选择已索引条目

#### Scenario: 简化操作并同步点赞选项
- **WHEN** 用户使用点赞索引抽屉
- **THEN** 系统自动选中主页面“点赞”，仅提供“继续浏览”和“重置”两个主要操作；前者自动创建或恢复，后者经确认清除当前来源缓存和位置后从头加载

### Requirement: 按来源隔离持久化索引

系统 MUST（必须）通过列表来源类型和来源所有者标识索引。本次变更 MUST（必须）只能创建点赞列表来源的索引，同时身份模型必须能表示未来的收藏夹来源，并避免其条目与点赞来源混合。

#### Scenario: 不同来源的索引保持隔离
- **WHEN** 后续从另一个列表来源索引到相同 aweme ID 的作品
- **THEN** 该未来来源的条目不得仅因 aweme ID 相同而覆盖或被点赞列表索引条目去重
