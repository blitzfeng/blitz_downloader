## 背景

点赞作品接口只提供正向的 `max_cursor` 游标链。大型点赞列表一旦中断，无法可靠续拉；若想按更早的内容消费，也必须先经过此前的所有分页。现有实现又将数据保存在内存并由滚动加载驱动，加载数百或数千条时会增加内存、UI 渲染与重复请求成本。

## 变更内容

- 为指定用户的点赞作品列表新增可持久化、可恢复的浏览会话。
- 每页成功后记录服务端下发的续拉游标、已浏览条目、媒体展示缓存与最后浏览位置；恢复时从该位置附近显示，再继续向下加载。
- 已浏览条目从数据库分页读取，避免重新请求此前页面；媒体地址仅是可过期的浏览缓存，下载时仍重新解析。
- 浏览按需拉页，不会为了上限预先遍历整个点赞列表；始终保留服务端游标原值，不能把它解释为页码。
- 识别陈旧、无效或已耗尽的持久化游标，并提供以作品 ID 去重的安全重新索引路径。
- 本次仅支持点赞列表；索引来源标识与数据契约需为未来支持收藏夹保留扩展空间，但不接入收藏夹。

## 能力

### 新增能力

- `resumable-liked-list-index`：持久化、恢复、校验并消费有上限的点赞列表分页索引。

### 修改的能力

- 无。

## 影响

- 受影响代码：`DouyinListApi`、`ListDownloadViewModel`、列表下载 UI、Room 实体/DAO/数据库迁移，以及下载任务选择路径。
- 行为影响：点赞列表将拥有明确的索引生命周期和持久化续拉边界；作品、收藏、收藏夹和合集列表的既有流程保持不变。
- 依赖影响：不新增网络接口或第三方库，复用既有点赞请求签名与 Room/KSP 迁移约定。
