## 2. 一致快照与成功发布

- [ ] 2.1 按设计实现事务内逻辑快照，完整复制表、类型、索引、触发器、视图、版本及 Room identity，正确处理 sqlite_sequence；设备测试验证当前实际 schema 全表覆盖，发现不支持的结构明确失败。
- [ ] 2.2 实现目标独立只读校验、行数/结构核对、字节数与 SHA-256 校验；测试包含 BLOB、空值、Unicode、外键及 WAL 中未 checkpoint 的已提交记录，损坏输出不得发布。
- [ ] 2.3 实现唯一 pending 目录、完成 manifest 与最终重命名发布，移除关闭共享数据库连接的行为；注入复制失败、空间不足和重命名失败，验证成功时间与原备份不变，半成品不进入恢复列表。
- [ ] 2.4 实现旧 DB/WAL/SHM 副本的隔离验证；设备测试确认旧副本可读取、不修改原目录，新单文件可在独立 Room 实例打开并继续写入。
- [ ] 2.5 在备份说明中补充发布协议、快照范围和资源限制；并发写入测试确认输出属于一致事务视图且业务数据库可继续操作，记录事务等待与总耗时。
