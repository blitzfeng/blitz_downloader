# Proposal

## Why

数据库回退到旧备份后，大量仍在手机上的视频、图集和证据帧没有对应下载记录。需要一个可预览、可复核、可续跑、写入前有独立备份的恢复流程，以重新关联本地文件和真实作品，保护已恢复及后来新增的数据。

## What Changes

- 设置页增加“恢复失联记录”，新增 Compose + Material 3 恢复页面、候选复核和批次历史。
- 第一版扫描固定下载目录及证据帧，提取作品 ID，使用已有登录态调用项目与 F2 对齐的作品详情接口，完成本地匹配和人工确认。扫描、查询和审核只写恢复暂存数据。
- 优先覆盖带 ID 文件和 `<awemeId>_evidence_<序号>.jpg`；没有 ID 的文件保留待处理，也可由用户补充作品链接。自动按作者分页、昵称搜索与当前收藏夹召回留到下一阶段，不混入本版实施任务。
- 备份成功且验证通过后，以显式确认的批次新增下载记录；采用只插入、重复跳过、事务内记账，禁止 REPLACE 和整库覆盖。
- 新增恢复来源与历史未知标识，避免将无法追回的观看、导出、标签编辑历史伪装为零，禁止制造人工标签反馈。
- 恢复保护默认开启，保持自动备份/清理停用，恢复前备份单独保留；迁移失败不能清库。

## Capabilities

### New Capabilities

- `lost-media-recovery`: 本地失联文件扫描、作品详情补全、候选匹配审核、备份后批量新增与恢复历史的完整生命周期。

### Modified Capabilities

无。`home-shell-navigation` 的三 tab 外壳、设置页旧备份恢复入口保持不变；`camera-video-organization` 的相机文件移动能力不属于本次恢复流程。

## Impact

- 新增恢复 Repository、DAO/Entity、前台任务服务、ViewModel、Activity 和 Compose 复核界面；以当前 Room v31 为基线设计 v32 迁移，实际实施若已升版则顺延。
- 接入 SettingsFragment、BlitzApp、已有登录态、媒体访问与播放导出流程，以及备份协调器。管理页显示恢复来源和历史未知状态，并在筛选时区分这些记录。
- 不需要 AI Key，不上传视频或证据帧到 AI，不重下载或重命名本地媒体；网络仅向现有抖音接口请求用户触发的作品详情。
- 本变更不以未验收的 `auto-backup-database` 为发布依赖。独立验证恢复前快照能力，并保留自动任务关闭状态。
- 盘点方法见[总体恢复方案](../../../docs/lost-video-data-recovery-plan.md)，实现见[技术设计](design.md)。当前验收进度和换机步骤分别记录在[任务清单](tasks.md)及[验收与交接记录](../../../docs/media-recovery-validation.md)。
