# 失联媒体与下载记录恢复方案

旧数据库恢复后，手机的公共下载目录可能仍有原视频、图集、封面和 AI 证据图。目标是找出有文件但缺少下载记录的作品，并保护用户在恢复旧库之后添加的下载和标签。

## 从哪些线索恢复

| 本地线索 | 可以做什么 |
| --- | --- |
| 文件名中的作品 ID | 向抖音查询作品详情，再核对本地文件类型、时长或图集成员。 |
| 证据图文件名中的作品 ID | 查到作品后，在本地比较封面和视频帧。只有证据图时保留为待绑定。 |
| 作者昵称、相同文案 | 缩小人工查找范围。同名作者或同一作者的多条相同文案均需查看画面。 |
| 作品链接 | 为没有 ID 的本地媒体补充作品身份，进入普通查询和审核流程。 |

作品详情可补齐作者、描述、作品发布时间及可核验的公开字段。观看、导出、原下载时间、人工标签和 AI 判断历史只能从已有备份或后续真实操作取证。首版使用作品详情接口。按已确认的作者 ID 分页查找作品、核对喜欢或收藏夹来源，是后续候选功能。[F2 接口说明](https://f2.wiki/guide/apps/douyin/overview)

## 实施顺序

1. 在旧库上核对下载记录、标签和关联。原始副本与工作副本分别保存。
2. 只读扫描 `Download/bDouyin` 下的视频、图集、封面和证据图，分别统计文件、作品 ID 和已有记录。一个 ID 可以对应多个文件。
3. 对有 ID 的候选请求详情，在手机上对照本地文件。保留同作者同文案的各个候选，确认图集成员和主图。
4. 人工确认并预览后，每批最多 50 个作品先备份再写入。已存在的作品跳过，原文件保留。通过恢复历史查看实际写入数和待处理项。

早先已经完成旧备份的恢复与核对。本次 v32 恢复功能的验收使用独立模拟器及合成数据。个人盘点数量、原始备份、文件清单和核对摘要保存在原电脑的 `recovery-local/`。若需要跨电脑核对同一现场，可经私人渠道单独复制该目录；新电脑开发、构建及模拟器验收只需仓库文件。
