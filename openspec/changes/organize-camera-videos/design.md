## Context

动机见 [proposal.md](proposal.md)，行为契约见 [spec.md](specs/camera-video-organization/spec.md)。现有应用 minSdk 24、targetSdk 36，设置页已具备所有文件访问权限跳转，用于下载目录相册隐藏；当前没有相机目录整理能力。现有下载数据使用 Room，整理对象不属于应用下载记录。

本次默认范围为主共享存储、直接子文件、手动批次和固定前缀，不扩展至 SD 卡或递归扫描。文件跨目录移动及旧系统权限差异需要明确设计，避免将读取权限误当作删除授权。

## Goals / Non-Goals

**Goals:**
- 分离纯筛选规则、存储操作与界面，便于验证移动失败时的文件保留行为。
- 所有 IO 离开主线程，单一执行器串行处理批次并提供可观察结果。
- 在应用支持的系统版本上采用适合的访问路径，授权不足时不写盘。

**Non-Goals:**
- 不鉴定真实拍摄来源，不做内容去重、自动任务、后台保活服务或一键撤销。
- 不修改数据库 schema，不将外部视频导入下载管理，不改动既有下载目录相册隐藏逻辑。

## Decisions

### 1. 目录扫描与纯规则独立

在 `model/` 放置候选快照、结果类型、前缀规则和冲突命名规则；在 `data/` 放置有状态整理执行器及存储适配。直接文件扫描使用系统公共目录 API 解析主存储路径，校验规范化父目录，不跟随链接。Android 10 通过授权的文档树枚举直接子项。

媒体类型使用系统 MIME 信息或扩展名 MIME 映射；`video/*` 按 `img`、`vid` 前缀排除，路由至 `history`；`image/*` 按 `img`、`mvimg`、`pano`、`retouch` 前缀排除，路由至 `history_img`，因此 `VID_001.jpg` 仍需移动。未知类型保守跳过，不按内容识别拍摄来源。前缀直接使用忽略大小写的 `startsWith`，不额外要求下划线、数字或词边界。候选保存路径或文档身份、原名、大小、修改时间和 MIME，执行前重新检查，无法取得可靠快照的文件跳过并说明原因。

直接文件适配与 SAF 适配均按当前候选 MIME 选择目标，只创建当前需要的子目录。候选预览逐项显示目标目录，批次可以同时包含两种媒体，计数与进度统一按文件计算。

替代方案：仅查询 MediaStore 较简单，但可能遗漏未索引文件；递归扫描扩大误移动范围，因此不采用。

### 2. 按 Android 版本适配权限

| 系统 | 访问方案 | 授权取消后的行为 |
|---|---|---|
| Android 11+ | 复用 `MANAGE_EXTERNAL_STORAGE` 检查和系统设置跳转，以直接文件 API 操作 | 提示未授权并结束本次操作 |
| Android 6–9 | 申请 Manifest 已声明的读写外部存储运行时权限 | 不扫描或移动 |
| Android 10 | SAF 授权主存储 `DCIM/Camera` 和 `Download` 文档树，在 Download 下管理 history | 目录不符或未授权则提示并结束 |

SAF 只接受可验证为目标主存储目录的系统外部存储文档树，不把任意目录当成替代来源；可持久保存 URI 授权，下次检查是否仍有效。Android 11+ 不走 Download 树选择方案。授权返回继续扫描预览，绝不跳过确认。

替代方案：仅提供 Android 11+ 功能会缩小现有系统支持范围；全版本统一使用裸文件路径在 Android 10 的分区存储下不可靠，因此保留三种适配。

### 3. 单批次状态与 Compose 交互

设置页底部接入一个 Compose 入口，卡片背景复用既有设置项的 `color_card_background`，圆角 12dp、阴影高度 1dp，与其他设置项保持一致。新建预览、进度和结果界面，弹窗复用 `ComposeDialogFragment`、`BlitzTheme` 和 `FragmentResult`。预览显示全体候选，确认全部移动，不新增逐项选择功能。

整理执行器仅持 application context，拥有 IO coroutine scope、互斥控制和结构化 `StateFlow`；作为应用进程内单实例，存活于屏幕旋转及 tab 切换，保存最近一次结果至下一次操作。状态采用空闲、扫描、待确认、移动、已结束，含批次 ID；确认只接受当前待确认 ID，以防重复回调。界面订阅使用 `repeatOnLifecycle`，文案留在视图层，不把文件 IO 或弹窗状态塞入现有 SettingsViewModel。

仅在进程存活时保证任务继续；进程重启不恢复执行。预览重建但找不到对应批次时提示重新扫描，不持久化待执行的删除指令。

替代方案：Fragment 自身启动长批次会受视图销毁影响；前台服务和持久任务队列超出本次手动小功能的范围。

### 4. 移动采用不覆盖的提交过程

同名序号在扩展名前插入，保留扩展名；批次内及提交时都检查占用。禁止采用可能覆盖目标的裸 `renameTo`，禁止先删除源文件再复制。

直接文件适配优先使用经过验证的同卷、不覆盖移动原语；平台不支持可靠原语或走 SAF 时，退化为复制流程：在目标目录创建唯一临时文件，流式复制并计算摘要，关闭后重新读取目标校验字节数和摘要，再校验源状态未变化，使用不覆盖的方式提交最终文件，确认最终文件完整后才删除源。如果 provider 不能保证不覆盖提交，则独占创建新目标并复制校验，不使用覆盖式重命名。

复制异常保留源，清理由本批次创建的临时文件；清理失败显示残留位置。删除源失败时记为失败，保留完整目标副本并在结果中列出位置，后续重扫不按名称推断已完成或静默删除源。对预览后变化、零字节、仍在写入或无法确认稳定的文件跳过。

进程死亡可能留下完整副本或临时文件，因此仅记录本功能创建的临时文件身份用于下次提示清理；不根据文件名通配删除目录内容，不自动删除源或正式目标。已成功移动的文件不会再次出现在源扫描中。

替代方案：无校验复制后立即删除会放大复制错误的数据损失风险；统一复制虽简单，但耗时和临时空间较大，故保留可靠同卷移动优化。

### 5. 媒体同步与结果分离

移动成功后对新位置触发媒体扫描，并对旧位置同步失效索引。直接文件路径使用系统媒体扫描能力，SAF 结合 provider 更新结果及可用的系统媒体接口处理；实现时需在不同系统验证旧项移除。不要通过删除媒体 URI 来“刷新”尚未确认失效的文件。

文件移动结果与索引刷新结果分开，刷新失败只产生附加提示。原先就被 `.nomedia` 隐藏的目标遵循系统现状，本功能不创建或删除 `.nomedia`。不写入应用下载记录。

## Risks / Trade-offs

- 文件名不等于来源 → 明示规则并预览；大小写与 `video` 前缀纳入测试。
- 扫描后外部应用继续写入 → 执行前及复制后检查快照，变化项跳过；无法对外部写入提供跨进程事务保证。
- 复制需要额外空间且大视频校验较慢 → 优先可靠同卷移动，IO 线程显示进度；不足时保留源。
- 不同设备的文档 provider、媒体扫描行为不同 → Android 10 SAF 与 Android 11+ 真实公共存储各做设备验证；拒绝无法验证范围的 provider。
- 进程死亡可能留下副本 → 不自动重试删除，临时文件按本功能记录清理，完整副本由用户核对。

## Migration Plan

无需数据库迁移。发布前完成纯规则与失败注入测试、Debug 构建、分版本权限和公共目录真机验收。功能入口上线后仅由用户手动触发。

回退代码只移除入口和执行器，不反向搬动已经整理的视频；视频仍位于 `Download/history`，图片位于 `Download/history_img`，用户可使用文件管理器手工移回。
